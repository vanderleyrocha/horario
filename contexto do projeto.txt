Sistema de Geração Inteligente de Horários Escolares com Algoritmo Genético Modular desenvolvido em PHP, Laravel 12 e LiveWare 4
1. Visão Geral

O projeto consiste na implementação de um Sistema Inteligente de Geração de Horários Escolares baseado em Algoritmo Genético (AG), desenvolvido sob uma arquitetura modular, desacoplada e orientada a domínio.

O objetivo é construir um motor genético genérico e reutilizável (módulo AG) e, sobre ele, implementar o problema específico de geração de horários escolares (módulo Horários), garantindo:

Separação rigorosa entre domínio do problema e engine evolutiva

Escalabilidade matemática

Evolução incremental da estratégia genética

Integração controlada com frontend via progress reporting

Persistência estruturada de métricas e diagnósticos

2. Princípios Arquiteturais

O projeto segue os seguintes princípios:

2.1 Arquitetura Modular

Separação clara entre:

Modules/
 ├── AG         → Engine genética genérica
 └── Horarios   → Problema específico de horário escolar

A engine não conhece:

Eloquent

Models Laravel

Banco de dados

Livewire

UI

O módulo Horários não contém lógica evolutiva.

2.2 Clean Architecture Adaptada

Divisão interna do módulo AG:

AG
├── Domain
│   ├── Core
│   ├── Operators
│   ├── Fitness
│   ├── Termination
│   ├── Repair
│   ├── Metrics
│   └── Analysis
├── Application
├── Infrastructure
└── Support

Domain → lógica matemática pura

Application → orquestração da engine

Infrastructure → geração de população e cache

Support → DTOs, exceções e erros estruturados

3. Objetivos Técnicos
3.1 Resolver o Problema NP-Difícil de Geração de Horários

O sistema deve:

Evitar conflitos professor/turma

Respeitar carga horária

Considerar aulas duplas/triplas

Minimizar janelas

Melhorar distribuição semanal

Considerar bloqueios obrigatórios e preferenciais

3.2 Implementar Fitness Estruturado

Fitness dividido em:

Penalidades Hard (inviabilizam solução)

Penalidades Soft (otimizam qualidade)

Resultado formal:

FitnessResult:
- score
- totalPenalty
- hardPenalty
- softPenalty

Maximização como padrão.

3.3 Implementar Diagnóstico Estrutural Pré-Execução

Antes de rodar o AG:

Análise de saturação global

Sobrecarga por turma

Sobrecarga por professor

Deficit de blocos contínuos

Índice matemático de risco (0–100)

Classificação qualitativa (MINIMO → CRITICO)

Execução pode ser bloqueada automaticamente se risco crítico.
