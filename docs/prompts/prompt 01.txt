<?php

namespace App\Modules\AG\Domain\Metrics\DTO;

class GenerationMetrics
{
    public int $generation;

    public float $bestFitness;

    public float $avgFitness;

    public float $variance;

    public float $diversity;

    public float $entropy;

    public float $mutationRate;

    public int $stagnation;

    public function __construct(
        int $generation,
        float $bestFitness,
        float $avgFitness,
        float $variance,
        float $diversity,
        float $entropy,
        float $mutationRate,
        int $stagnation
    ) {
        $this->generation = $generation;
        $this->bestFitness = $bestFitness;
        $this->avgFitness = $avgFitness;
        $this->variance = $variance;
        $this->diversity = $diversity;
        $this->entropy = $entropy;
        $this->mutationRate = $mutationRate;
        $this->stagnation = $stagnation;
    }
}

Este DTO é 100% matemático (sem dependência de Laravel).

3️⃣ ExecutionMetricsRecorder

Este componente fica em Infrastructure, pois escreve no banco.

AG\Infrastructure\Metrics\ExecutionMetricsRecorder.php
<?php

namespace App\Modules\AG\Infrastructure\Metrics;

use Illuminate\Support\Facades\DB;
use App\Modules\AG\Domain\Metrics\DTO\GenerationMetrics;

class ExecutionMetricsRecorder
{
    private int $executionId;

    public function startExecution(
        int $scheduleId,
        int $populationSize,
        int $generations,
        array $parameters
    ): int {

        $this->executionId = DB::table('schedule_executions')->insertGetId([
            'schedule_id' => $scheduleId,
            'start_time' => now(),
            'population_size' => $populationSize,
            'generations' => $generations,
            'parameters_json' => json_encode($parameters)
        ]);

        return $this->executionId;
    }

    public function recordGeneration(GenerationMetrics $metrics): void
    {
        DB::table('schedule_generation_metrics')->insert([
            'execution_id' => $this->executionId,
            'generation' => $metrics->generation,
            'best_fitness' => $metrics->bestFitness,
            'avg_fitness' => $metrics->avgFitness,
            'variance' => $metrics->variance,
            'diversity' => $metrics->diversity,
            'entropy' => $metrics->entropy,
            'mutation_rate' => $metrics->mutationRate,
            'stagnation' => $metrics->stagnation
        ]);
    }

    public function finishExecution(float $bestFitness): void
    {
        DB::table('schedule_executions')
            ->where('id', $this->executionId)
            ->update([
                'end_time' => now(),
                'best_fitness' => $bestFitness
            ]);
    }
}
4️⃣ Integração com MetricsRecorder

O MetricsRecorder calcula as métricas e entrega o DTO.

MetricsRecorder
public function collectGenerationMetrics(
    int $generation,
    array $population,
    float $mutationRate,
    int $stagnation
): GenerationMetrics {

    $best = $this->bestFitness($population);
    $avg = $this->averageFitness($population);
    $variance = $this->variance($population);

    $diversity = $this->diversityCalculator->calculate($population);
    $entropy = $this->entropyCalculator->calculate($population);

    return new GenerationMetrics(
        $generation,
        $best,
        $avg,
        $variance,
        $diversity,
        $entropy,
        $mutationRate,
        $stagnation
    );
}

🔟 RiskIndex Matemático (Viabilidade)

Seu conceito é extremamente válido.

Sugestão formal:

RiskIndex = w1*S + w2*C + w3*E + w4*B

onde:

S = saturation ratio
C = constraint density
E = structural entropy
B = block deficit ratio

Normalização:

RiskIndex ∈ [0,100]

Classificação:

Range	Status
0–20	baixo
20–40	moderado
40–60	alto
60–80	crítico
80–100	inviável
